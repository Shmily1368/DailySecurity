# 每日采集与发布

网站以北京时间 08:37 为目标更新时间。GitHub Actions 在 07:47 开始采集，08:07、08:27 进行幂等重试，09:07 再做一次延迟恢复。GitHub 的定时启动和外部来源不提供准点 SLA；提前启动和重试用于降低延迟概率。

`daily.yml` 将采集、离线检查、数据提交、构建和 Pages 发布串成一条依赖链。构建固定使用本次实际数据提交的 SHA，发布前检查该 SHA 仍是 main 最新提交，防止旧构建覆盖新数据。代码 push 与手动部署复用同一套 `deploy.yml`，不再使用无法绑定数据提交的 `workflow_run`。

如果今天的健康快照已发布、线上 `health.json` 的日期、数据 SHA 和提交 SHA 与实际检出版本一致，定时执行跳过重复采集和构建。健康快照尚未发布时只补部署；来源降级时重试采集。生产工作流不提供 mock 开关。

## 快照与失败恢复

```bash
python scripts/run_pipeline.py
```

管线持有本机文件锁，以最多四个子进程并发采集独立来源；基础来源完成后再查询 OSV 和 EPSS。默认单源预算 240 秒，CI 使用 180 秒。所有模型分组共享 120 秒可选预算；必要的本地日报组装独立使用 90 秒，不依赖模型 API。

退出码、数据双校验、来源元信息和子来源状态共同决定成功与否。来源失败只回退该来源的状态，其他可用数据继续发布。所有基础来源失败则保留上次日报；健康来源真实无新增时允许发布空日报。发布失败保留上一代；同日重跑保留当天已经验证的论文和事件。

`data/current.json` 是权威入口，指向同一代的 `digest.json`、`index.json` 和 `state/`，并包含摘要文件 SHA256。新代在同一文件系统暂存、完整校验后，以原子替换入口提交；保留当前和上一代。跨日切换前必须将上一天最后一代完整归档，归档失败则保留旧入口。历史日报继续读取 `data/daily/YYYY-MM-DD.json`，无需重写历史数据。flat latest、raw、processed 和 state 仅作为兼容镜像。

子进程超时和取消会回收整个进程组。模型遇到余额或鉴权错误后跨组熔断；成功摘要按输入、模型和 Prompt 指纹缓存。不可用时发布真实「来源摘录」，不会偷偷改成演示数据，也不会给摘录加模型评分。

## 数据真实性

来源日期未知时 `published_at=null`，展示「首次发现」或「仅知年份」，不把抓取时间当成发表时间。未知日期的首次发现时间随快照持久化。OpenAlex 摘要需要完整标题及年份匹配；历史研究推荐与当日新论文分开。

HTML 来源只提取经过配置的文章区域、链接和同容器日期。不能识别布局时明确标记失败，避免把导航页当公告、把来源不可用当成无新增。RSS/API 保留逐条容错和来源级错误；TLS 验证保持开启。来源可访问性可能随地区、限流或站点改版变化。

CVSS、严重度、KEV、公开 PoC 和修复版本均按原始来源证据处理；KEV 不等于存在公开 PoC。单漏洞的 NVD/GHSA/OSV/KEV 记录聚合并保留副来源及别名；多漏洞文章保持独立。Schema 与 Pydantic 通过 `python scripts/sync_schemas.py` 可重复同步，前端类型兼容历史记录。

## 网站体积与交互

历史聚合和主题索引只在构建中计算一次；日期读取使用有界缓存。首页首次只输出十条精选，分类和搜索按当前页渲染，每页最多二十条，不再用 CSS 隐藏整个日报。

搜索覆盖本期日报的 CVE、原始 ID、别名、副来源、厂商、产品、标签和完整摘要；清空搜索保留原分类页码。历史通过日归档和主题归档访问，两个归档均静态分页。主题目录每页一百个名称；大小写主题按规范身份合并，保留原主题 URL。`config/topic-slugs.json` 固定现有路径，新主题使用内容指纹后缀，不会因插入标签改变旧数字后缀的含义。旧 URL 的名称碰撞展示相关主题合集，同一路径的大小写别名展示相同内容。

详情按二十条一个文件输出为带内容 SHA 的 `.json.gz`，点击后由浏览器 `DecompressionStream` 解压。列表只显示短摘要，完整摘要、关联标识、副来源和修复依据按需加载。需要支持该标准的现代浏览器；原始来源链接和静态分页不依赖详情脚本。

`health.json` 包含日报日期、数据 SHA、数据提交、构建时间、来源状态及模型/摘录数量。已打开首页定期使用带时间参数的请求检查版本，发现更新后提示刷新；日期落后时明确展示最近有效日报。它描述数据和构建状态，实际部署时间以 Pages 记录为准。

## 验证与诊断

```bash
pip install -r requirements-dev.txt
python -m pytest scripts/tests -q --tb=short
python scripts/check_pipeline.py
python scripts/publication.py validate
cd src
npm ci
npm run check
npm run build
cd ..
python scripts/check_site.py
DATA_COMMIT=<实际数据提交SHA> python scripts/publication.py verify
```

Python 回归自动禁止外部 socket，并覆盖来源日期、摘要身份、分页续抓、熔断、评分、当日事件留存、取消、锁和发布故障。前端检查类型、真实数据索引和旧路径；产物验收检查分页、详情文件、路径及大小，不把构建退出零当成验收完成。

`data/tmp/pipeline/status.json` 保存步骤状态，同目录保存来源和摘要日志，Actions 无论成功或失败均上传为 artifact，保留十四天；临时目录和锁不进入 Git。查看故障时先核对来源状态、快照 SHA、构建数据提交和线上 manifest，再定位对应步骤。

`python3 scripts/watch_publication.py` 可从独立于 GitHub cron 的环境核对公开网站与 main 提交。加 `--recover` 时，仅在版本或日期落后且没有正在运行的更新/部署时触发现有 Daily 工作流；触发成功不代表已部署。恢复认证使用环境中的 `GITHUB_TOKEN` 或仓库本机入口的 credential helper，不向任务或日志复制凭据。独立定时任务依赖其执行环境、网络与认证可用。
